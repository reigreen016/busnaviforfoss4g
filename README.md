## リアルタイム表示

「現在日時に戻す」を押すと、収録期間内の現在日付・時刻を使ってリアルタイム情報を反映します。現在日時のモードは会場を切り替えても維持します。開催日・過去日・固定時刻・参考ダイヤでは現在の遅延情報を混ぜません。

- 通常版busnaviと同じCloudflare APIを共有：https://busnavi-realtime.rnp9cf8k76.workers.dev/api/realtime
- 取得を一か所に集約し、両サイトの全利用者合計で各社への取得は最短30秒間隔。
- 画面は30秒ごとに確認し、非表示中・過去日時では停止。
- 配信元の更新から90秒超の情報、便や停留所を照合できない予測は使いません。
- 遅延便は元の予定時刻に小さな取り消し線を付け、補正後の発車時刻を赤字で表示。補正後の時刻で昇順に整列。
- 取得した予測が予定どおりなら緑字の「定刻」、未取得なら「予定」と表示。
- 取得できた運休・停車取りやめは案内から除きます。追加便の生成や未取得区間への遅延推測は行いません。
- 到着予測は明示的なarrival情報がある場合のみ反映。下車停留所のdeparture予測を到着時刻に読み替えません。

APIの管理コード・更新手順は通常版busnaviリポジトリのworkerフォルダで管理します。このサイト用に別のAPIを設置する必要はありません。

配信元：https://www.bus-kyo.or.jp/gtfs-open-data （CC0）

## 表示・言語

左側の乗り場図と右側の発車案内を、同じ幅・高さで表示します。直近便カードは置かず、先頭20便を案内します。狭い画面では縦並びになります。

下車停留所を会場名の隣に表示し、先頭の停留所を赤、2つ目をオレンジで区別します。図と発車案内の乗り場番号は同じ2秒間隔で切り替えます。発車まで3分以内の行も同期して強調します。図の対象は各停留所に向かう次の便から3分以内の乗り場です。23・20・17番の停留所略号は番号の左側に配置します。非点灯側も淡い色で表示します。

提供されたFOSS4Gロゴの隣にbusnaviを表示し、赤を基調とします。フォントはHelvetica / Arialと端末の日本語フォントを使用し、外部フォントは取得しません。

日本語・英語・韓国語・簡体字・繁体字に対応。停留所・会社・行き先はGTFSのtranslations.txtを使用し、未翻訳は日本語を残します。原図内の文字は日本語です。

## データと軽量化

4社のGTFS ZIPから3,188件の出発候補を生成しています。出発は乗車可能な「広島駅」の完全一致で、北口（新幹線口）発を含みません。下車停留所が出発より後のstop_sequenceにあり、降車可能な便を選びます。運行カレンダー・例外日・前日運行の24時超に対応します。乗り場番号の未収録は推測しません。

- 広島バス：2026-10-09〜2027-04-09
- 広島電鉄：2026-10-27〜2027-04-27
- 広島交通：2026-10-10〜2027-04-10
- JRバス中国：2026-10-25〜2027-04-25

乗り場図は1824×2336の高画質WebP（品質95、449,750バイト）です。元PNGの6,224,310バイトから約93%削減し、文字・線の見やすさを拡大比較しています。優先読み込み・非同期デコード・寸法指定も行っています。

時刻表は必要な運行カレンダー・例外日・翻訳だけを残し、4,290,301バイトから1,478,866バイトに軽量化しました。全出発候補・会場・開催日・必要な運行日は維持しています。

データ更新：

```sh
python3 scripts/build_data.py /path/to/GTFSフォルダ
python3 scripts/verify_gtfs.py /path/to/GTFSフォルダ
```

## ローカル確認・公開

```sh
npm start
npm test
```

http://127.0.0.1:8000/ を開いてください。実行時の外部パッケージは不要です。

自動テストでは全会場・平日・週末・開催日の参考ダイヤ・遅延時の並び替え・運休・情報の古さ・非表示時停止・過去日へのリアルタイム混入防止を検証します。verify_gtfs.pyでは全3,188件と必要なカレンダーを元GTFSへ照合します。

GitHub Pagesはmainブランチのdocsフォルダを公開します。編集後、次を実行して公開ファイルを更新し、コミット・pushしてください。

```sh
python3 scripts/prepare_pages.py
```
